> **文档性质**：在《Velrix-SpringBoot重写需求文档.md》M1 节基础上，对齐 **AAA 仓库已落地的 M0**，给出可分批实施、可验收、可写测试的执行规格。  
> **与 M0 文档关系**：结构沿用 `docs/M0-平台底座需求.md`（背景 / 功能编号 / 决策 / 验收 / 接口 / 概念模型）；本文增加 **DDL 要点、分包、任务切片、引用影响 SPI、与 M2/M3 的接缝**。  
> **状态**：草案 v0.1  
> **最后更新**：2026-10-17  
> **仓库前提**：Flyway 当前 **V16**；**新迁移从 V17 起**；Java 包根 `com.velrix`；M0 已实现 JWT、RBAC、`@RequirePerm`、`BizException`、`ApiResponse`（见 `HandOff.md`）。

## 1. 背景与目标

### 1.1 背景

主数据是库存、采购/销售、核销等模块的**前置依赖**。Velrix 课表在 CRUD 之外强调两件事：

1. **停用代替物理删除**（历史单据仍展示引用到的主数据）。
2. **删除前引用影响查询**（有引用则拒绝删除并给出分类型数量）。

M0 已在用户维度采用「仅停用、不物理删」；M1 将同一产品策略扩展到商品、仓库、客户、供应商。

### 1.2 产品一句话

**管理员维护 ERP 基础档案**：商品、仓库（含库位与库位容量）、客户、供应商；支持启用/停用；删除前展示引用影响；为后续入库/下单提供「必须启用」校验入口。

### 1.3 v0.1 目标（本里程碑可交付）

| 目标 | 说明 |
|------|------|
| 档案 CRUD | 四类主数据可增删改查（删受 R1-2/R1-3 约束） |
| 编码唯一 | 创建与更新均校验；库内 `trim + 大写` 规范化（对齐主文档 §3.3） |
| 停用 | `PATCH …/status`；停用后**不得用于新业务**（由门禁接口供 M2/M3 调用） |
| 引用影响 | `GET …/impact` 返回分类型 `count`；有任意引用则 `DELETE` 返回 **409** |
| 仓库结构 | 仓库下库位；库位对商品的容量上限配置 |
| 权限与菜单 | Flyway 种子菜单 + `@RequirePerm`；写操作记审计（对齐 M0 习惯） |

### 1.4 非目标（M1 不做）

- 库存流水、余额、入库/出库接口（**M2**）；AC1-2 的「不能登记入库」在 M2 接门禁后联调验收。
- 采购单/销售单实体与状态机（**M3**）；影响查询中「采购单/销售单」计数由 **M3 注册 Contributor** 后才有真实值。
- 批次/序列号业务行为（**M2**）；M1 仅在商品上维护 `batch_managed` / `serial_managed` 标志供后续使用。
- 前端精美 UI；列表 + 表单 + 启停 + 删除前影响弹窗即可。
- 多租户、导入导出、主数据审批流、版本历史表。

## 2. 用户与权限（菜单）

### 2.1 角色

沿用 M0：**系统管理员**配置主数据；**采购员**等角色是否只读由种子或后续授权决定（v0.1 建议：管理员全权 + 可选只读角色一条演示）。

### 2.2 建议菜单树（Flyway 种子，ID 段避免与 2000/2100 冲突）

| 节点 | path（前端） | 类型 | perm_code（按钮） |
|------|----------------|------|-------------------|
| ERP | `/erp` | MENU | — |
| 商品管理 | `/erp/products` | MENU | — |
| 新建/编辑/停用/删除 | — | BUTTON | `product:create` / `product:update` / `product:status` / `product:delete` |

## 4. 产品决策（实施前定稿）

| ID | 决策点 | 选项 | 建议（M1 v0.1） |
|----|--------|------|-----------------|
| D1 | 主键 | 雪花 / 应用侧递增 / DB 自增 | 与 M0 一致：**应用侧 `Long` 主键**（若全局尚未统一 ID 生成器，M1 任务 0 先落地 `IdGenerator` Bean） |
| D2 | 无引用时是否允许物理删除 | 仅停用 / 允许删 | **仅停用**（与 M0 用户策略一致，删除 API 可不做或始终 409 提示改用停用） |
| D3 | 编码规范 | 仅 trim / trim+大写 | **trim + 大写** 存 `code_norm` |
| D4 | 库位删除 | 允许 / 仅停用 | v0.1 **不允许删有容量配置的库位**；空库位可删 |
| D5 | 影响查询扩展方式 | 模块内 if-else / SPI | **SPI：`MasterDataImpactContributor`**，按 `MasterDataKind` 注册 |
| D6 | 停用 API 形态 | PUT 整实体 / PATCH status | **PATCH `/status`** `{ "status": "INACTIVE" }` |
| D7 | 包名 | `masterdata` 模块 | `com.velrix.masterdata.{domain,application,infrastructure,web}` |

**定稿区：**

```
D1: 应用侧 Long 主键（IdGenerator / MP 雪花）
D2: 仅停用、不物理删主数据（仓库线 DELETE 库位：空库位可物理删）
D3: trim + 大写 → code_norm
D4: 有容量配置不可删库位；空库位可删；FK RESTRICT 兜底
D5: SPI MasterDataImpactContributor（T3 实现）
D6: PATCH …/status
D7: com.velrix.masterdata.*
```

## 5. 数据模型（Flyway V17+）

### 5.1 表清单

| 表 | 说明 |
|----|------|
| `md_product` | 商品 |
| `md_warehouse` | 仓库 |
| `md_location` | 库位 |
| `md_location_capacity` | 库位-商品容量 |
| `md_customer` | 客户 |
| `md_supplier` | 供应商 |

### 5.2 DDL 要点（实现时拆成 V17～V22 或多表一版本）

**公共约定**（对齐 M0 `sys_user`）：

- `id BIGINT PK`，`created_at` / `updated_at` `DATETIME(3)`
- 状态枚举 **VARCHAR(50)**：`ACTIVE` / `INACTIVE`
- 数量阈值 `DECIMAL(18,6)`；金额本模块无

**`md_product`**

- `code`, `code_norm`（`uk(code_norm)`）
- `name`, `unit`, `status`
- `max_inventory_qty` NULL
- `batch_managed`, `serial_managed` `TINYINT(1)`

**`md_warehouse`**

- `code`, `code_norm`（唯一）
- `name`, `address`, `status`

**`md_location`**

- `warehouse_id` FK → `md_warehouse`
- `code`, `code_norm`（**`uk(warehouse_id, code_norm)`**）
- `name`

**`md_location_capacity`**

- PK `(location_id, product_id)` 或 surrogate id + unique
- `max_qty DECIMAL(18,6) NOT NULL`

**`md_customer` / `md_supplier`**

- `code`, `code_norm`, `name`, `status`
- `contact_name`, `contact_phone`, `address`（可 NULL）

### 5.3 索引与双保险

- 唯一索引 + Service 层先查再插（捕获 `DuplicateKeyException` 转友好文案），对应主文档「唯一索引与业务校验双保险」。

## 6. 引用影响查询（R1-3）

### 6.1 响应结构（建议）

```json
{
  "code": "OK",
  "data": {
    "deletable": false,
    "message": "存在业务引用，请停用并保留历史数据",
    "items": [
      { "refType": "PURCHASE_ORDER", "label": "采购订单", "count": 3 },
      { "refType": "SALES_ORDER", "label": "销售订单", "count": 5 },
      { "refType": "INVENTORY_TXN", "label": "库存流水", "count": 20 },
      { "refType": "INVENTORY_ON_HAND", "label": "当前在库", "count": 1, "quantity": "12.000000" }
    ]
  }
}
```

- `deletable = items 全部 count==0`（在库 quantity 为 0 视为无引用）。
- `DELETE` 与 `impact` 共用同一聚合逻辑。

### 6.2 Contributor SPI

```text
MasterDataImpactService
  └─ List<MasterDataImpactContributor>
        kind() → PRODUCT | WAREHOUSE | CUSTOMER | SUPPLIER | LOCATION
        contribute(entityId) → List<ImpactItem>
```

| refType | M1 默认 | 实现方 |
|---------|---------|--------|
| `INVENTORY_TXN` / `INVENTORY_ON_HAND` | 0 | **M2** 注册 |
| `PURCHASE_ORDER` | 0 | **M3** |
| `SALES_ORDER` | 0 | **M3** |
| `LOCATION_CAPACITY` | 真实 COUNT | M1 本地 |

**M1 验收 AC1-1（有流水不可删）**：在 M2 未合并前，用 **集成测试 TestConfiguration** 注册 stub Contributor 返回非零；M2 合并后改为真实 Mapper COUNT。

## 7. 接口清单

路径与主文档一致；响应壳为 `ApiResponse`；冲突 **HTTP 409** + `code=BIZ_ERROR`（或与全局约定扩展 `BIZ_CONFLICT`）。

| 方法 | 路径 | perm | 说明 |
|------|------|------|------|
| GET/POST | `/api/products` | list/create | 分页列表 + 创建 |
| GET/PUT | `/api/products/{id}` | list/update | 详情 + 更新 |
| PATCH | `/api/products/{id}/status` | status | 启停 |
| GET | `/api/products/{id}/impact` | list | 引用影响 |
| DELETE | `/api/products/{id}` | delete | 无引用才可删（或 D2 禁用） |
| GET/POST/PUT | `/api/warehouses` … | 同上 | 仓库 CRUD + status |
| POST | `/api/warehouses/{id}/locations` | location:manage | 增库位 |
| GET/PUT | `/api/locations/{id}` | location:manage | 库位改名称等 |
| PUT | `/api/locations/{id}/capacities` | location:manage | 覆盖容量 |
| GET | `/api/locations/{id}/impact` | — | 可选 |
| CRUD | `/api/customers` `/api/suppliers` | customer:* / supplier:* | 含 impact + status |

**领域规则落点**：编码唯一、状态迁移、容量 > 0 等写在 **domain 实体方法** 或小型 domain service；Application 只编排事务与调 Mapper。

## 8. 验收场景

与主文档 **AC1-1、AC1-2** 及演示剧本对齐。

| 编号 | 场景 | 预期 |
|------|------|------|
| AC-M1-01 | 新建商品编码 ` sku-01 ` | 存为 `SKU-01`；重复创建 409/业务错误 |
| AC-M1-02 | 更新商品编码与他人冲突 | 拒绝 |
| AC-M1-03 | 商品 impact 任一项 count>0 时 DELETE | **409**；message 含「采购订单 3 张…」类摘要 |
| AC-M1-04 | 停用商品后 `ProductGuard.requireActive` | 抛业务异常 |
| AC-M1-05 | 仓库下建库位；容量 max_qty=0 | 422/业务错误 |
| AC-M1-06 | 库位 A 配置商品 P 容量 100 | PUT 覆盖后仅保留新列表 |
| AC-M1-07 | 停用仓库 | status=INACTIVE |
| AC-M1-08 | 停用仓库后 `WarehouseGuard.requireActiveForInbound` | 拒绝（**AC1-2**；M2 入库接口联调同场景） |
| AC-M1-09 | 无 `product:list` 权限调列表 | 403 |
| AC-M1-10 | 管理员创建客户并停用 | 列表可见 INACTIVE；M3 下单门禁拒绝 |

**主文档映射**

- AC1-1 → AC-M1-03（stub 或 M2 真实流水）
- AC1-2 → AC-M1-08 + M2 入库 E2E

## 9. 实施任务切片（推荐顺序）

| 阶段 | 内容 | 产出 |
|------|------|------|
| **T0** | 定稿 §4；`IdGenerator`（若缺）；建 `com.velrix.masterdata` 包 | 空模块可编译 |
| **T1** | Flyway V17～V19：product + warehouse + location + capacity | DDL + 实体 + Mapper |
| **T2** | Product/Warehouse Application + Controller + 审计 + 菜单种子 V20 | Postman 可 CRUD |
| **T3** | `MasterDataImpactService` + PRODUCT/WH 本地 contributor；PATCH status；Guard 类 | AC-M1-03/04/07/08 单测 |
| **T4** | Customer/Supplier + impact + guards | CRUD 全通 |
| **T5** | 集成测试：`@SpringBootTest` + Testcontainers MySQL（Flyway 全量）；权限 403  case | CI 可跑 |
| **T6** | 最小 React 页（可选） | 演示启停与 impact 弹窗 |

**测试策略**

- 每个 **R1-x** 至少 1 个领域/应用单测（编码唯一、容量、停用）。
- 403/401 沿用 M0 模式；`GlobalExceptionHandler` 断言 HTTP 状态。
- 不要求 M1 并发 🔒 用例（并发在 M2）。
